## Фичи

### 1. Динамический состав здания
Люди привязаны к зданию через `building_id`. Приезжают/уезжают:
- **Прибытие** → добавляем запись в `people` с `building_id` текущего здания, `active=1`
- **Уезд** → `active=0`. История дежурств сохраняется
- **Возврат** → снова `active=1` (та же запись)
- **Нет переводов** между зданиями — один человек, одно здание

### 2. Отсутствия
Человек не может дежурить на весь период:
- Таблица `absences`: person_id, period_id, reason
- Причины: болезнь, отсутствие, прочее
- При просмотре периода — отсутствующие помечены специальным образом

### 3. Автозамена
При отсутствии человека система автоматически ищет замену:
- Тот же пол
- Не отсутствует сам
- Не занят в эту комнату в этот день
- Назначается переназначение

### 4. Личный профиль
Клик на имя в боковой панели → карточка:
- Полная история дежурств по периодам
- Какие помещения, какие дни
- Статистика по комнатам

### 5. Рейтинг / очередь на дежурство
Сортировка по количеству дежурств (меньше = выше):
- Кто меньше всех дежурил — кандидат на следующий период
- Цветовая индикация: зелёный (мало), жёлтый (норма), красный (много)
- При создании периода — автоподбор из топа рейтинга

### 6. Гибкий период
Не обязательно неделя. Период может быть 1, 3, 7 дней:
- `periods.num_days` определяет количество дней
- Даты отображаются的真实 календарные дни

### 7. Копирование периода
Дублирование назначений в новый период с новыми датами

### 8. Непрерывность периодов
Периоды идут последовательно один за другим, независимо от того, создаёт ли их кто-то.
- Кнопка «Следующий период» — автоматически создаёт период сразу после текущего (та же длительность, дата = конец текущего + 1 день)
- Видно: если текущий период — 21.07–27.07, следующий будет 28.07–03.08

### 9. Автозаполнение периода
При создании или после создания периода — кнопка «Заполнить автоматически»:
- Берёт рейтинг (кто меньше всех дежурил)
- Назначает людей по порядку рейтинга на все помещения и дни
- Учитывает: пол помещения, не назначать дважды в одну комнату в один день
- Не назначает отсутствующих
- Результат: полностью заполненная таблица, которую можно докорректировать вручную

### 10. Ручной ввод истории
На бумаге ведётся история ~1 год. Нужно перенести в систему.
- Режим «Ввод истории»: создаётся период с прошлой датой, заполняется вручную как обычно (кликом по ячейкам)
- Период помечается как «из истории» (не текущий, просто данные)
- Цель: чтобы рейтинг и статистика были полными с первого дня
- API: обычные эндпоинты назначений, просто фронтенд позволяет создавать периоды с любыми датами
